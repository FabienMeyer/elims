# Product and engineering principles

1. Specifications are the contract for substantial changes.
2. Safety, security, privacy, accessibility, and data integrity are not optional optimizations.
3. Every component owns its behavior and documentation beside its code.
4. Public APIs and data migrations remain explicit and reviewable.
5. Verification evidence must match the approved acceptance criteria.
6. Generated assets and automated decisions retain provenance.
7. System documentation describes the implementation that exists, not an intended future state.
